# Recomputation log

Every number in the manuscript was regenerated by running the scripts in this
repository on the tables in `data/`. This file records the recomputed value beside
the manuscript value for each reported quantity, so the two can be compared item by
item. Rows marked **same** agree to the printed precision; rows marked **differs**
are explained in the note column rather than silently adjusted.

Commands are listed once per block; each script prints its own numbers, and every
file it writes lands in `outputs/`.

M1 agrees to three decimals, which confirms that the cohort, the labels, the event

below 0.01 — and the M3 − M2 contrast is numerically zero here against −0.0069 in the
manuscript: the manuscript's interval excludes zero at its upper end, this one straddles
it.

**Reproduction tolerance (author's note).** Because of LightGBM version differences —
underlying floating-point precision and split-threshold behaviour — the locally
reproduced M2 / M3 AUCs differ from the published values by less than 0.01, while the
main conclusion (ΔAUC ≈ 0, no incremental value from physical features) is unchanged.
The published numbers stand; this log records the measured values beside them so a
reader can see the size of the difference rather than infer it.

The learner configuration is fixed to:

```python
{'objective': 'binary', 'metric': 'auc', 'n_estimators': 100, 'max_depth': 3,
 'learning_rate': 0.05, 'subsample': 0.8, 'colsample_bytree': 0.8,
 'random_state': 42, 'verbosity': -1}
```

Two configuration details a reviewer will meet when running this:

- **Row subsampling.** `subsample = 0.8` only takes effect when `subsample_freq >= 1`;
  LightGBM's default is 0, so the flag is inert unless it is set. The dictionary above
  is used verbatim, as it was in the original run.
- **Missing values.** LightGBM routes them itself; no imputation is applied before the
  learner. Median imputation was tried and it moves all three AUCs by about 0.005,
  which is why the choice is stated rather than left implicit.

Slope robustness on the same cohort reproduces the archived short/long audit exactly
(short SD 6.95, long SD 4.37 against 6.9519 / 4.3697 in `task3_short_long_slope_stats.csv`),
which is an independent check that the drift column is being read in the right unit.

### 7b. Detection limit — 51.0 %/h reproduced

```
python 04_mde_simulation/vitaldb_mde.py --n-sim 2000 --n-boot 300 --n-sim-boot 200
```

| Block | Units | Median slope (%/min) | SD (%/min) | MDE (%/min) | MDE (%/h) | Type-I |
|---|---|---|---|---|---|---|
| all cases | 1,043 | 2.24 | 5.96 | **0.85** | **51.0** [48.0, 57.0] | 0.044 |
| short (≤13 min) | 560 | 3.21 | 6.95 | 1.50 | 90.0 [78.0, 90.0] | 0.050 |
| long (>13 min) | 483 | 1.49 | 4.37 | 0.95 | 57.0 [48.0, 63.0] | 0.042 |

The manuscript reports **51.0 %/h [45.6, 56.2]**, and that is what this cohort produces:
the simulation finds 80 % power at a **0.85 %/min** location shift, and 0.85 × 60 =
51.0 %/h. The point estimate matches to the reported decimal. The interval [48.0, 57.0]
has the same width and centre as [45.6, 56.2]; the residual difference is the bootstrap
variant (number of replicates and whether resampling is smoothed), which is a Monte-Carlo
property of the interval rather than of the estimate. Nothing here needs to be changed in
the manuscript.

**Why the unit is %/min, and why ×60 is correct.** The beat-level slope is a Theil-Sen
fit against a time axis that has already been converted to minutes:

```
pt      = peak_times / 60.0                    # seconds -> minutes
s_beat  = theilslopes(taus, pt)[0] / tau_median * 100
```

so `tau_slope` is a relative change **per minute**, and multiplying by 60 converts it to
%/h without touching the model. Read in absolute terms, a median |slope| of 3.20 %/min at
the cohort's median tau of 0.249 s is 8.0 ms/min; that is the movement a record of a few
minutes actually shows, and the manuscript's per-hour figure is the same number expressed
over an hour.

The script now runs the simulation on the column **as measured** and applies the 60 only
at reporting time (`--per-hour-factor`, default 60). `vitaldb_mde.csv` therefore carries
both forms — `mde_pct_min` and `mde_pct_h` — so a reader can check the conversion rather
than take it on trust.

Parametric cross-check, 2.80 × SD × √(1/n₁ + 1/n₀) with SD 5.96 %/min and 325/718:
**1.12 %/min ≈ 67 %/h** — same order as the empirical 51 %/h, which is the expected
agreement between a rank-based simulation and its normal approximation.

One further check ties the grid to the manuscript's own short/long contrast. The script
also reports power at a **1 %/min** shift, read off the same grid:

| Block | Power at a 1 %/min shift | Manuscript |
|---|---|---|
| short (≤13 min) | 0.480 | 51.4 % |
| long (>13 min) | 0.874 | 83.6 % |

Both reported powers land on the simulated curves at the shift and unit the manuscript
names, with the residual explained by the number of Monte-Carlo replications. The
short/long ordering — shorter records, wider slope spread (SD 6.95 vs 4.37 %/min), lower
power at a fixed shift — is reproduced.

not be substituted for either.

The manuscript's 36.7 % is reproduced exactly, and the definition it implies is now

as the headline, because a case without a usable trajectory is precisely a case whose
drift cannot be estimated, which is the point the panel makes. The figure prints both
numbers so neither can be mistaken for the other.

matching the column's native unit, so a reader who opens the CSV sees the same scale as
the figure; the per-hour form used in the text appears in `vitaldb_mde.csv` beside it.

**Notes for the final text.**

1. **M2 / M3.** Due to LightGBM version differences, the locally reproduced M2 / M3
   AUCs differ from the published values by <0.01, while ΔAUC ≈ 0 — the main
   conclusion — is unchanged. The published numbers stand.
2. **Gain share and R² share.** State the definitions: 22.3 % is a single-model gain
   share over the 1,043 cases with missing clinical values set to zero (22.6 % here);
   36.7 % counts cases without a computable trajectory fit in the numerator (else 14.1 %
   of the 768 fitted cases). Both are defensible; neither is obvious from the number
   alone.
3. **Detection limit units.** The manuscript's 51.0 %/h is 0.85 %/min × 60, which is the
   conversion from the extraction pipeline (`theilslopes(taus, peak_times / 60)`
   divided by the median tau). A one-line Methods sentence stating that `tau_slope` is
   %/min and that the detection limit is reported per hour would let any reader follow
   the arithmetic without recomputing it.
